# Resolve a SwissTiming RSC to a RaceBoard URL

`rsc_raceboard.py` resolves an RSC within a specific SAP Sailing event. It prints
exactly one URL to stdout on success and reports missing/ambiguous matches to
stderr with a nonzero exit status.

For an HTTP redirect endpoint hosted by AWS Lambda behind an Application Load
Balancer, see [rsc_raceboard_lambda.md](rsc_raceboard_lambda.md).

## Run

Requires Python 3.8+ and only the standard library. No package installation or
virtual environment is needed. From the repository root:

```sh
python3 scripts/rsc_raceboard.py \
  00502e4a-1c08-455b-8e22-280840638a39 \
  SALW49ERFX------------PREL000200--
```

For this Paris 2024 event, the script discovers the TracTrac feed from the event's
`trackingConnectorInfos[].webUrl`. Explicitly specifying the feed also works:

```sh
python3 scripts/rsc_raceboard.py \
  00502e4a-1c08-455b-8e22-280840638a39 \
  SALW49ERFX------------PREL000200-- \
  --tractrac-url https://event.tractrac.com/events/event_20240727_ParisOlymp/jsonservice.php
```

Discovery supports TracTrac `/event-page/event_.../ID` URLs.
For events without such a URL, supply `--tractrac-url`; it can be repeated.
Explicit feed URLs replace discovery. The Tokyo event currently has no TracTrac
`webUrl`, so its corresponding feed must be supplied explicitly.

The bundled Properties parser supports CR/LF line endings, comments, whitespace
and `=`/`:` separators, escaped keys and values, Unicode escapes, continuation
lines, and last-assignment-wins semantics for duplicate keys.

Use `--server https://YOUR-SERVER` to query another SAP server. URLs use the event's
`baseURL`, falling back to the queried server if none is configured. Paris 2024's
configured base URL is `https://paris2024.sailing.omegatiming.com`.

## Lookup and event scoping

1. Read `/sailingserver/api/v1/events/{eventId}` and its `leaderboardGroups`.
2. Read `/sailingserver/api/v1/leaderboardgroups/{groupId}` for each referenced
   group. Its response already embeds
   `leaderboards[].series[].fleets[].races[]`, so no per-leaderboard requests are
   needed.
3. Consider only entries with `isTracked: true` and `trackingProviderType:
   "TracTrac"`. These expose `raceId`, `regattaName`, and `trackedRaceName`.
4. Parse the TracTrac metadata using Java Properties syntax and find UUIDs whose
   `ExternalId` equals the requested RSC. Intersect those UUIDs with the race
   attachments reached in step 3. Race names are never used as join keys.
5. Construct a URL with `eventId`, `leaderboardName`, `leaderboardGroupId`,
   `regattaName`, `raceName`, `showMapControls=true`, and `mode=PLAYER`.

An RSC need not be globally unique, or even unique across the supplied feeds.
Only matching UUIDs reachable from the chosen event qualify. A leaderboard column
name such as `R2` is not the tracked race name and is not used as `raceName`.

If several viewing contexts qualify, use `--leaderboard-group UUID` and/or
`--leaderboard 'Exact name'`. Repeated attachments with identical group,
leaderboard, regatta, tracked race name and UUID are deduplicated. Untracked race
columns and unlinked races in the same regatta are excluded.

The group response may already include `raceViewerUrls[eventId]`, generated by
`RaceBoardLinkFactory`. The script constructs the same context from the fields so
that it also works without that optional field and URL-encodes every query value,
including the leaderboard name.
