SAP Sailing Analytics Webservices API Version 1.0

URL: /sailinglandscape/api/landscape/movetoarchiveserver/async

Description:

Starts archiving an application replica set, including content comparison and any requested database archiving and replica set removal. Archiving is long-running; this asynchronous pattern is preferred, particularly to avoid client or proxy timeouts. The synchronous endpoint remains available for clients that depend on receiving the final results in the POST response.

Webservice Type: POST
Output format: json (application/json;charset=UTF-8)
Form parameters: Accepts exactly the synchronous endpoint's form parameters as application/x-www-form-urlencoded, with the same defaults: durationToWaitBeforeCompareServersInMilliseconds=300000, maxNumberOfCompareserverAttempts=5, removeApplicationReplicaSet=true, and force=false.
Permissions: LANDSCAPE:MANAGE:AWS and, when removing the source replica set, permission to delete its SERVER. Source and archive credentials must permit master-data export and import, respectively.

Acceptance

The request waits for preparation and for the archive to accept the master data import (MDI), then returns HTTP 202 Accepted. Preparation can still take time; timeoutInMilliseconds only limits replica set discovery, not the entire request. Importing, comparison and cleanup continue in the background independently of client polling. Acceptance does not mean archiving has completed or succeeded.

Before acceptance, live content conflicts return HTTP 409 Conflict with the same conflict body as the synchronous endpoint; missing replica sets and other archiving exceptions return HTTP 400 Bad Request.

Example request (replace the credential placeholders):

curl -X POST \
  -H 'Authorization: Bearer <landscape-token>' \
  -d 'regionId=eu-west-2' -d 'replicaSetName=my-event' -d 'keyName=my-key' \
  --data-urlencode 'privateKeyEncryptionPassphrase=<passphrase>' \
  --data-urlencode 'bearerTokenForReplicaSetToArchive=<source-token>' \
  --data-urlencode 'bearerTokenForArchive=<archive-token>' \
  'https://sapsailing.com/sailinglandscape/api/landscape/movetoarchiveserver/async'

Example response, HTTP 202 Accepted:

{
  "progressTrackingUuid": "1f07d1cf-0652-4fc3-83bc-a79612a5aa68",
  "archiveHostname": "archive.sapsailing.com"
}

Polling import progress

Use the returned archiveHostname and progressTrackingUuid to poll the archive's existing MDI progress endpoint, for example every five seconds:

curl -H 'Authorization: Bearer <archive-token>' \
  'https://archive.sapsailing.com/sailingserver/api/v1/masterdataimport/progress?progressTrackingUuid=1f07d1cf-0652-4fc3-83bc-a79612a5aa68'

Authenticate with credentials having master-data import permission on the archive, normally the token supplied as bearerTokenForArchive, or the initiating user's token when that parameter was omitted. Progress is replicated; allow a bounded initial delay for HTTP 404 while replication catches up. Progress expires one hour after import completion, so do not retry HTTP 404 indefinitely. Report authentication/permission errors.

The progress JSON includes overallProgressPercent, failed and errorMessage. Stop polling on failed=true, or when a non-null result indicates successful import; a percentage alone is not a completion signal.

The UUID tracks only the master data import. Import success does not establish that content comparison, database archiving or replica set removal has finished or succeeded. Those steps continue in the background; the final archiving outcome is logged and emailed to the initiating user, both replica set owners, and users with master-data export permission on the source or import permission on the archive. Each user receives one outcome email, in their locale, if their email address is verified. Failures after import acceptance are also emailed. This endpoint does not provide a pollable final archiving result.
