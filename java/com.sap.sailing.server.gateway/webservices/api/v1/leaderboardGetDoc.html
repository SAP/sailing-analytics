SAP Sailing Analytics Webservices API Version 1.0

URL: /api/v1/leaderboards/{name}

Description:

Scoring configuration is included even for empty results and untracked columns, including flexible leaderboards: scoringScheme is the scoring scheme enum name (for example LOW_POINT). Each column in trackedRacesInfo includes isMedalRace, the effective numeric factor, nullable explicitFactor (null means use the scheme's default), and oneAlwaysStaysOne (a score of one remains one when scaling). The factor includes any explicit override; Medal defaults depend on the scoring scheme. Column entries follow columnNames order and are present without a tracked race. For regatta leaderboards, series-local discard/reset/carry settings are available from /api/v1/regattas/{name}.

The service gets the details of a leaderboard


Webservice Type: REST
Output format: Json
Mandatory parameters: None
Optional parameters: resultState [Live = Default, Final]
secret: in case the given secret is equal to the one stored in a regatta with the same name as the {name}, further security checks will be skipped
  maxCompetitorsCount [1000 = Default]
 
competitorAndBoatIdsOnly [Default = false, true] if true, only IDs and no further attributes will be delivered for competitor and boat JSON objects in the result document. This can help save bandwidth if the competitor and boat data have been received already during previous calls and the current call is only an update. Note, however, that competitor and boat data may change, so every now and then it is advisable to still set this to false to obtain the full up-to-date fields for all competitors and boats again.
  includeUncorrectedTotalPoints [Default = false, true]: if true, compute and include uncorrectedTotalPoints in each score cell under competitors[].raceScores. This is the score before score corrections; totalPoints remains the corrected score and netPoints retains its existing meaning. Requested but unavailable uncorrected scores are represented as JSON null, like other unavailable score fields. When absent or false, the field is omitted and uncorrected scores are not computed. Computing these scores can be expensive, especially for unfinished competitors in large fleets. Client migration: the field was previously included by default and incorrectly duplicated totalPoints; clients that need uncorrected scores must now explicitly opt in. Example: /sailingserver/api/v1/leaderboards/{name}?includeUncorrectedTotalPoints=true.
Request method: GET
Example: http://www.sapsailing.com/sailingserver/api/v1/leaderboards/505 Worlds 2013
